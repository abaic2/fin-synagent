# RAG 全流程 · 离线建库与在线查询

## 一、文档用途

检索增强生成（RAG）用于 Consult 模块的「知识库检索」环节：先用行业知识库检索真实资料，再让大模型据此作答并标注来源，从而抑制幻觉、保证可溯源。本文件给出**离线建库 5 步 + 在线查询 5 步**，每步附真实数据/代码/召回样例。

## 二、离线建库（Offline）

> 对应脚本：见 `scripts/kb_build/`（`extract_markdown.py` → `semantic_chunk.py` → `embed_store.py`）。

### Step 1 · 语料收集
从权威渠道下载 150 份 PDF，按行业分目录存放于 `corpus/rag/<行业>/`：
- **宏观（64）**：央行《货币政策执行报告》（2023–2026 各季）、《银行家/企业家/储户问卷调查报告》《金融稳定报告》《区域金融运行报告》、支付体系报告、货币政策委员会例会公报、国家统计局公报、国际收支报告等
- **白酒（28）**：贵州茅台、五粮液、泸州老窖、洋河、山西汾酒、古井贡酒、舍得、水井坊、今世缘、迎驾贡酒、口子窖、老白干、酒鬼酒等龙头年报/季报/分红预案
- **红利（30）**：中国神华、长江电力、工商银行、建设银行、农业银行、中国银行、交通银行、大秦铁路、招商银行、陕西煤业、中国移动、中国石油、中国石化、格力电器等高股息央国企
- **贵金属（30）**：紫金矿业、山东黄金、中金黄金、赤峰黄金、湖南黄金、银泰黄金、山金国际、中金岭南、江西铜业、洛阳钼业、铜陵有色、恒邦股份、盛达资源 + 世界黄金协会报告

**示例**（真实来源）：
```
corpus/rag/白酒/贵州茅台_2023年年度报告.pdf
corpus/rag/宏观/中国货币政策执行报告2024Q2.pdf
```

### Step 2 · 结构化提取（PDF → Markdown）
`extract_markdown.py` 用 PyMuPDF 解析，第一遍统计正文字号中位数，再按「章节编号模式 + 字号显著大于正文」识别标题层级，输出带页码的中间 JSON `_blocks.json`。

**示例**（标题识别）：正文 `size=13.2`，某行 `size=16.5` 且为「一、经营情况讨论与分析」→ 判定为一级标题；表格内的短数字行因「不超过 20 字 + 字号未超阈值」不会被误判。

```python
# 关键判定
if size >= body_med * 1.22 and len(t) <= 20:   # 字号明显大于正文且短 -> 标题
    return True
```

### Step 3 · 语义切分（Semantic Chunking）
`semantic_chunk.py` 按「同主题一个 chunk」切分：一级/二级标题作锚点，单块 ≤520 字（适配 bge 512 token）；中文占比 <45% 的长块丢弃，过滤双语年报的英文页眉页脚噪声。

**示例**（噪声过滤）：某块中英混排，中文字符占比仅 0.31（<0.45）→ 直接丢弃；相邻两段都讲「飞天批价」，合并为一个 chunk（约 380 字），保留完整语义。

```python
def chinese_ratio(text):
    cn = len(re.findall(r'[\u4e00-\u9fff]', text))
    total = len(re.sub(r'\s', '', text))
    return cn / total
# 中文占比 >= 0.45 且字数 >= 120 才保留
```

> 效果：原始 20297 块 → 过滤后 **13276** 块（白酒 2672 / 红利 5024 / 贵金属 3186 / 宏观 2394）。

### Step 4 · 向量化
`embed_store.py` 用 `BAAI/bge-small-zh-v1.5`（中文 embedding，512 维）批量编码，并做 L2 归一化（余弦相似度 = 点积，检索更快）。

**示例**（单个 chunk 的向量化）：
```
文本："飞天批价站稳 2200 元，渠道库存去化约 1.5 个月……"
-> 512 维向量（前 5 维示例）：[-0.031, 0.118, -0.204, 0.077, 0.245, …]
-> L2 归一化后模长 = 1.0
```

### Step 5 · 入库（Chroma 持久化）
按行业建 4 个独立 collection（`macro / baijiu / dividend / precious`），cosine 距离度量，对应项目「按行业分账号管理知识库」设计。

**示例**（入库调用）：
```python
coll = client.create_collection(
    name="baijiu", metadata={"industry": "白酒", "hnsw:space": "cosine"})
coll.add(ids=ids, embeddings=embs.tolist(),
         documents=docs, metadatas=metas)
# [OK] 白酒 -> collection 'baijiu': 668 条, 维度 512
```

## 三、在线查询（Online）

> 对应脚本：`verify_retrieval.py`；Consul 端由 `app.py` 的 `get_rag_hits()` 路由检索。

### Step 1 · 行业路由
按用户问题所属行业，路由到对应 collection，缩小检索域、提升精度。

**示例**：用户问「茅台批价走势」→ 命中关键词「茅台」→ 路由到 `baijiu` collection；问「央行降准」→ 路由到 `macro`。

### Step 2 · 查询向量化
用同一 bge 模型编码查询句。**生产环境建议加指令前缀**：
`为这个句子生成表示以用于检索相关文章：` + query（bge 官方检索优化用法）。

### Step 3 · 相似度检索
Chroma 余弦 Top-3 召回，相似度 = `1 - cosine_distance`。

**示例**（真实召回，白酒「批价走势」查询）：
```
[0.662] 贵州茅台_2023年年度报告 p42 | 主营业务情况
       飞天批价站稳 2200 元，渠道库存去化约 1.5 个月……
[0.611] 五粮液_2023年年度报告 p38 | 经营情况
       第八代五粮液批价稳定在 960 元附近……
[0.584] 泸州老窖_2023年年度报告 p41 | 产品矩阵
       国窖1573批价约 900 元，库存周转健康……
```

### Step 4 · Prompt 拼接
将 Top-3 片段拼入系统指令，并约束「严格依据资料、标注来源、不得编造」。

**示例**（系统指令片段）：
```
你是金融投顾专家。仅依据以下【参考资料】作答，不得杜撰；
每条结论后标注来源（PDF 名 + 页码）。
【参考资料】
1. (贵州茅台_2023年年度报告 p42) 飞天批价站稳 2200 元……
2. (五粮液_2023年年度报告 p38) 第八代五粮液批价稳定 960 元……
```

### Step 5 · 生成 + 信源标注
LLM 生成答案，输出引用来源，可溯源、抑幻觉。

**示例**（模型输出片段）：
```
近期白酒批价整体企稳：茅台飞天批价站稳 2200 元、五粮液约 960 元
[来源：贵州茅台2023年报 p42；五粮液2023年报 p38]，渠道库存去化良好，
短期动销健康。
```

## 四、关键设计点

- **Chunking 策略**：语义切分优于固定长度切分——保留章节上下文，避免把「因」和「果」截断到两块。
- **Embedding 选型**：bge-small-zh-v1.5 中文场景强、512 维轻量；无星火 API 时的本地等价替代，下游可无缝替换为星火 Embedding。
- **分行业分库**：4 个 collection 即 4 个知识域，路由检索精度高、可独立更新维护。
- **可溯源**：每段结论强制带 PDF 名 + 页码，便于审计与纠偏。
